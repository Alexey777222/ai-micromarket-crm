# MicroMarket Control

> CRM-система для управления сетью микромаркетов с автоматическими рекомендациями пополнения, учётом партий по FEFO и дашбордом собственника.

| Версия | 0.2.0 |
| Лицензия | Частный проект (portfolio only) |
| Язык | Python 3.12–3.14 |
| Фреймворк | Django 5.2 |
| БД | SQLite (локально) / PostgreSQL 16 (продакшн) |
| Контейнеризация | Docker Compose |

## 📋 Описание

**MicroMarket Control** — это локальная CRM-система для автоматизации учёта и управления сетью микромаркетов (торговых витрин с холодильным оборудованием).

Система решает ключевые задачи розничного учёта:

- 📊 **Дашборд собственника** — выручка, валовая прибыль, списания, тренды
- 🛒 **Управление товарами** — партии, сроки годности, остатки в реальном времени
- ❄️ **Холодильное оборудование** — учёт по точкам: склад, холодильник, автомобиль, зона списания
- 📈 **Рекомендации к пополнению** — автоматический расчёт на основе FEFO
- 📦 **CSV-импорт продаж** — атомарная загрузка данных с оборудования
- 🤖 **Telegram-бот** — уведомления и команды `/start`, `/replenishment`
- 🔒 **Безопасность** — HTTPS, rate-limiting, разграничение ролей

> ⚠️ **Это демонстрационный пилот, а не промышленная система.** Все данные в репозитории синтетические. Реальных клиентов, организаций или персональных данных нет.

## 🚀 Быстрый запуск

### Требования

- **Windows:** Python 3.12–3.14
- **Linux:** Python 3.12, Docker Engine + Compose v2
- **macOS:** Python 3.12, Docker Desktop

### Вариант 1: Автоустановка (Windows)

```powershell
# 1. Установка
.\install_demo.bat

# 2. Запуск
.\start_demo.bat

# 3. Вход в браузере http://127.0.0.1:8000/
#    Логин: demo
#    Пароль: demo12345
```

### Вариант 2: Ручная установка

```powershell
# 1. Виртуальное окружение
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip setuptools wheel

# 2. Зависимости
.\.venv\Scripts\python.exe -m pip install -r requirements-web.txt

# 3. Миграции и демо-данные
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_business_demo

# 4. Статика и запуск
.\.venv\Scripts\python.exe manage.py collectstatic --noinput
.\.venv\Scripts\python.exe manage.py runserver
```

### Вариант 3: Docker Compose

```bash
# Локальный запуск с PostgreSQL
docker compose up --build

# Серверный режим (Linux)
python3 scripts/init_server.py
sh scripts/dev_certificate.sh
sh scripts/server.sh build
sh scripts/server.sh up -d
```

## 🔐 Безопасность

| Принцип | Реализация |
| --- | --- |
| Секреты в окружении | `.env` не попадает в репозиторий (`.gitignore`) |
| TLS | Self-signed для dev, доверенные сертификаты для prod |
| Rate-limit | Nginx: 5 запросов/мин на IP для входа |
| Разделение ролей | Владелец ≠ superuser |
| Production-mode | Блокирует DEBUG, weak SECRET_KEY, wildcard hosts |
| Read-only FS | Контейнер с `read_only: true` |
| Cap drop | `ALL` + минимальные привилегии |

### Что НЕ в репозитории

- `.env`, `.env.server` — переменные окружения
- `deploy/tls/` — TLS-сертификаты и ключи
- `backups/` — дампы БД
- `db.sqlite3` — базы данных
- `staticfiles/` — собранная статика
- `.venv/` — виртуальное окружение

## 📝 Известные ограничения

Проект является **пилотной версией** и имеет следующие ограничения:

1. Рекомендации к пополнению используют оценочный баланс (не исключают просроченные партии)
2. Импорт CSV не обрабатывает CANCELLED/REFUNDED отдельно
3. Распределение продажи по одной партии (FEFO, оценочное)
4. Нет автоматического продления TLS, MFA, мониторинга
5. Нет интеграции с amoCRM и платёжными системами
6. Полные формы редактирования справочников — в следующем этапе

> Подробно см. [`docs/KNOWN_LIMITATIONS.md`](docs/KNOWN_LIMITATIONS.md).
