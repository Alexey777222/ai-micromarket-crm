# MicroMarket Control v0.2.0 — локальная инструкция

Серверный запуск: docs/SERVER_SETUP.md. Владельцу размещённого сайта —
docs/OWNER_GUIDE.md. Ниже сохранён локальный способ тестирования на Windows.

Это демонстрационная (пилотная) версия системы учёта микромаркетов. Она
разворачивается локально на Windows и работает только на вашем компьютере.
Все данные в поставке синтетические — реальные организации, сотрудники,
клиенты и продажи в архив не входят.

---

## Первый запуск

1. **Распакуйте архив полностью.** Не пытайтесь запускать программу
   непосредственно внутри ZIP-архива — установщик работает только с
   распакованными файлами.
2. **Положите папку в короткий путь без кириллицы**, например:

   ```
   C:\MicroMarket\
   ```

   Длинные пути и путь с русскими буквами могут помешать работе Python и
   Django.
3. **Запустите `install_demo.bat`** двойным щелчком.
   - Установщик проверит Python, создаст виртуальное окружение `.venv`,
     установит веб-зависимости, применит миграции, соберёт статику и
     сформирует демонстрационную базу данных.
   - Установка занимает несколько минут. Не закрывайте окно, пока не
     появится сообщение об успешной установке.
   - Если что-то пошло не так, установщик покажет, на каком этапе
     произошла ошибка, и не будет выполнять следующие шаги.
4. **Дождитесь сообщения** «Установка MicroMarket Control v0.2.0 завершена».
5. **Запустите `start_demo.bat`** двойным щелчком.
   - В текущем окне поднимется локальный сервер Django.
   - Через несколько секунд автоматически откроется браузер.
6. **Откройте адрес** <http://127.0.0.1:8000/> (если браузер не открылся
   сам).
7. **Войдите** с учётной записью:
   - логин: `demo`
   - пароль: `demo12345`

## Повторный запуск

После первой установки повторно запускать установщик не нужно. Для
последующих запусков достаточно двойного щелчка по:

```
start_demo.bat
```

## Остановка

В окне сервера (там, где запущен `start_demo.bat`) нажмите:

```
Ctrl+C
```

Сервер остановится, окно можно закрывать.

## Что можно показать

- дашборд собственника с ключевыми метриками сети;
- 7 демонстрационных холодильников;
- 10 демонстрационных товаров;
- 4 100 демонстрационных продаж за 60 дней;
- выручку и валовую прибыль за 30 и 60 дней;
- списания и их долю от выручки;
- сроки годности партий и предупреждения об истечении;
- рекомендации по пополнению витрин;
- административную панель Django (русифицирована);
- товары, партии и движения между складами и витринами.

Данные рассчитаны так, чтобы выглядели правдоподобно: средний чек, доли
статусов оплаты, маржа и списания находятся в разумных пределах.

## Важные ограничения

- Это **локальный пилот**, а не готовая промышленная система.
- Все данные в поставке **синтетические**. Реальные данные владельца в
  архиве отсутствуют.
- **amoCRM пока не подключена** — интеграция с CRM находится в плане
  следующих этапов.
- **Telegram-бот является отдельным необязательным модулем**. Он
  устанавливается отдельно через `requirements-bot.txt` и в стандартную
  поставку не входит.
- Программу **нельзя считать готовой промышленной системой**.
- Демонстрационная учётная запись `demo / demo12345` и запуск через
  локальный сервер Django (`manage.py runserver`) **не пригодны для
  реальной эксплуатации**.
- Для промышленного запуска потребуются: отдельный сервер, HTTPS,
  резервное копирование, разграничение доступа по ролям и реальные
  интеграции (оборудование, CRM, платежи).

## Если что-то не работает

- Проверьте, что путь к папке короткий и без кириллицы.
- Проверьте, что установлен Python 3.12 или новее
  (<https://www.python.org/downloads/>).
- Перезапустите `install_demo.bat` — он безопасен для повторного запуска
  и не пересоздаёт данные без необходимости.
- Если нужно полностью пересобрать демо-базу, выполните в PowerShell из
  папки проекта:

  ```powershell
  .\.venv\Scripts\python.exe manage.py seed_business_demo --replace
  ```

  Эта команда пересоздаёт **только синтетические данные демонстрационной
  организации** (записи с префиксом `SYNTH-`).
