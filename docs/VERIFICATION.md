# Проверка сборки v0.2.0 — 17.09.2026

Это отчёт о проверках кода, а не акт запуска на сервере заказчика.
Публичного или приватного внешнего развёртывания не было. Рабочей ссылки пока нет.

Среда: Linux, Python 3.12.14, Django 5.2.17, SQLite для автоматических тестов.

- pytest: **119 passed**. Сохранены прежние 76 тестов и добавлены 43 проверки
  серверных настроек, доступа, новых страниц, bootstrap и упаковки.
- Ruff: All checks passed.
- pip check: конфликтов установленных зависимостей нет.
- manage.py check: замечаний нет.
- makemigrations --check --dry-run: новых миграций нет.
- collectstatic: файлы собраны и сжаты.
- HTTP-проверка через настоящий Gunicorn при DEBUG=0: вход, семь разделов,
  загрузка CSS, два пересчёта пополнения, выход и перенаправление гостя на вход.
  Скрипт scripts/http_smoke.py создаёт отдельную временную демо-БД и удаляет
  только её при завершении; рабочая база проекта не используется.
- Синтаксис shell-скриптов и YAML проверен. Это НЕ замена запуску Docker Compose.
- check --deploy с production-конфигурацией: два ожидаемых предупреждения
  security.W005 и security.W021. HSTS для всех поддоменов и preload сознательно
  выключены до выбора домена и проверки HTTPS на всех затрагиваемых адресах.

а последующая проверка обнаружила повреждённую SQLite-базу. Причина её повреждения
не установлена. Повторный прогон на новой изолированной БД прошёл. Ни эта база,
ни другие базы, сертификаты или реальные секреты в архив не включаются.

## Что должен проверить администратор перед передачей владельцу

1. В отдельном каталоге пройти SERVER_SETUP.md на пустой тестовой PostgreSQL-базе.
2. Убедиться, что контейнеры healthy, порт доступен только на loopback и без входа
   данные недоступны. demo/demo12345 не должен входить в production.
3. Войти владельцем, проверить поиск, страницы, смену пароля и выход.
   /admin/ для владельца должен возвращать отказ.
4. Дважды рассчитать пополнение: для одной даты/точки/товара не должно возникнуть
   дублей. Проверить повторный CSV-импорт: продажи и движения не должны удвоиться.
5. Сверить выручку, себестоимость, списания и остатки по контрольному набору.
   Учитывать ограничения бизнес-логики в KNOWN_LIMITATIONS.md.
6. Проверить мобильный экран и пользовательские ошибки CSV вручную.
7. Создать дамп, восстановить во временную БД, сверить данные. После перезапуска
   сервиса данные должны сохраниться. Настроить внешние копии и уведомления.
8. Только после согласования доступа настроить доверенный TLS и домен,
   повторить проверки на окончательном адресе и передать индивидуальный логин.

## Повторение локальных проверок

В отдельной тестовой копии проекта, с установленными requirements-web.txt:

```sh
python -m pytest -q
python -m ruff check .
python manage.py check
python manage.py makemigrations --check --dry-run
python -m pip check
```

HTTP-smoke требует Linux и Gunicorn из requirements-server.txt:

```sh
python scripts/http_smoke.py
```

Это вспомогательные действия разработчика, не инструкции владельцу бизнеса.
